# Публикации

Домен публикаций: площадки, источники, авторы, публикации, которые находят источники, и ссылки
из их текста. Здесь же запись публикации с итогом разбора, её автора и ссылок; роли публикации
пишет `saveVacancies` из `packages/db/src/vacancy/save-vacancies.ts` — её правила тоже здесь.

Функции записи принимают клиент или транзакцию drizzle и своей не открывают: границу транзакции
держит вызывающий — сейчас перенос постов (`apps/web/src/transfer`), потом движок. Сбой базы —
исключение drizzle, оно откатывает транзакцию вызывающего.

## API

Всё экспортирует `@job-market/db` (домен входит в `src/schema.ts`):

| Что                                                                                                           | Зачем                                                                                                                                                                                                                                                                  |
| ------------------------------------------------------------------------------------------------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `platforms`, `sources`, `authors`, `publications`, `publicationLinks`                                         | таблицы домена; значения столбцов — `CONNECTORS`, `PUBLICATION_STATUSES`, `LINK_STATUSES` из `@job-market/db/values`                                                                                                                                                   |
| `contentHash(content)`                                                                                        | хэш текста для поиска копий (П4)                                                                                                                                                                                                                                       |
| `findOriginals(db, hashes)`                                                                                   | оригиналы по хэшам: id по хэшу, хэша без оригинала в ответе нет (П4)                                                                                                                                                                                                   |
| `upsertAuthors(db, rows)`, `authorKey(connector, externalId)`, `AuthorToSave`                                 | вставка и перезапись авторов; ответ — id по `authorKey` (П3)                                                                                                                                                                                                           |
| `insertPublication(db, row)`, `PublicationToSave`                                                             | публикация с итогом разбора; `null` — её уже записал другой запуск (П6, E6)                                                                                                                                                                                            |
| `markFailed(db, row, error)`                                                                                  | публикация, разбор которой упал: `failed`, `last_error`, `attempts` + 1; `null` — как у `insertPublication` (П6)                                                                                                                                                       |
| `replacePublicationLinks(db, publicationId, links)`, `LinkToSave`                                             | ссылки текста публикации: прежние удаляются, новые пишутся по порядку, хост — по `targetUrl`, а без него — по `url`                                                                                                                                                    |
| `saveVacancies(db, publicationId, roles, { skipDuplicates? })`, `VacancyToSave`, `PlaceToSave`, `SaveSummary` | роли публикации и их места (П9, П17); компанию каждой роли ищет сама (П6, `packages/db/src/company/README.md`); с `skipDuplicates` не пишет дубли (П18–П20)                                                                                                            |
| `titleKey(title)`, `isSameRole(a, b)`, `DUPLICATE_WINDOW_DAYS`, `DuplicateFields`                             | правило дубля вакансии: название в одном виде, сравнение двух ролей, окно поиска (П18, П19)                                                                                                                                                                            |
| `getSource(db, id)`, `updateSourceSchedule(db, id, schedule)`, `SourceSchedule`                               | источник для движка (`undefined` — строки нет) и запись полей его расписания: пишет только переданные поля, `null` — как NULL, ничего не решает. Сбой базы — `Error` значением, а не исключение                                                                        |
| `claimDueSources(db, { now, connectorIds, limit })`, `releaseSources(db, claimed)`, `ClaimedSource`           | тик движка: одним запросом взять источники, которые пора опросить, и сдвинуть им `next_run_at` (`SKIP LOCKED`, П1 плана тика); вернуть прежний `next_run_at` тем, чьи задания не ушли (П3). Сбой базы — `Error` значением                                              |
| `claimPublication(db, id, { now, staleBefore, connectorIds })`, `ClaimedPublication`, `ClaimOptions`          | разбор движка: одним запросом взять публикацию `pending` или `processing` с `claimed_at` раньше `staleBefore` — `processing`, `attempts` + 1, `claimed_at` = now — и отдать её с автором; `undefined` — брать нечего (П1 плана разбора). Сбой базы — `Error` значением |
| `updatePublicationState(db, id, state)`, `PublicationState`                                                   | запись состояния разбора — `status`, `last_error`, `processed_at`, `duplicate_of_id`: пишет только переданные поля и только пока публикация `processing`, ничего не решает. Сбой базы — `Error` значением                                                              |

Ссылки одной публикации пишутся целиком: повторная запись перезаписывает их, как и вакансии.

## Правила

На номера правил ссылаются комментарии в коде. Номера — из плана переноса, поэтому с пропусками:
правила, которые выполняет только перенос, — в `apps/web/src/transfer/README.md`.

**Публикация и автор**

- **П3.** Один автор — одна строка по `(connector, external_id)`. Запись автора вставляет новую
  строку или перезаписывает у найденной `name`, `url` и `headline`, поэтому у автора значения
  последней записи; повтор одного автора во входе пишется один раз — последним значением. Какой
  `external_id` у автора, решает тот, кто пишет: путь профиля LinkedIn, канал Telegram.
- **П4.** `content_hash` — sha256 текста без строк рекламы соседних каналов («Больше вакансий в
  HR: https://t.me/forhr»): строка, которая начинается с «больше», «ещё» или «more» и кончается
  ссылкой на t.me. Пробелы сжаты в один, по краям убраны. Хэш считается по тексту автора, до
  разделов енричера. Оригинал хэша — публикация с этим хэшем и статусом `vacancy` или
  `not_vacancy`; из нескольких — самая ранняя по `(posted_at, id)`.
- **П6.** Публикация с тем же `(connector, external_id)`, но `failed` — повтор разбора: запись
  перезаписывает её текст, хэш, итог, автора и ошибку, `attempts` растёт на 1; id и источник
  остаются. Упавший разбор пишется `failed` с `last_error`, без причины «не вакансия», заметки и
  оригинала; новая такая публикация получает `attempts` 1.

**Вакансии и места**

- **П9.** Вакансия — одна роль публикации; `position` — номер роли в списке, с 0. Повторная
  запись той же публикации перезаписывает вакансии по `(publication_id, position)`: все столбцы,
  кроме ключа строки, `created_at` и поискового вектора, а столбец, которого нет в роли, получает
  свой DEFAULT. Лишние вакансии прежней записи удаляются. `schema_version` и `occupation_id`
  ставит тот, кто пишет: у `schema_version` нет DEFAULT, роли нового экстрактора приходят с 2.
- **П17.** Места вакансии пишутся в `vacancy_locations` той же транзакцией, что вакансия, по
  порядку: `position` — номер места в списке. Повторная запись удаляет прежние места вакансии и
  пишет новые. `vacancies.locations` — `raw` всех мест роли по порядку, включая «откуда угодно»,
  которого нет среди строк мест: по ним ищет `/vacancies`. Их собирает `locateVacancies` пакета
  `@job-market/geo/server`.

**Дубли вакансий**

- **П18.** Дубль — роль, которая уже сохранена вакансией из другой публикации: та же компания
  (`company_id`), то же название и нет противоречий. Название сравнивается по `titleKey`: Unicode
  NFKC, нижний регистр, ё → е, всё, кроме букв, цифр, «+» и «#», — пробел; слова не
  выбрасываются, «Frontend (React)» и «Frontend (Vue)» — разные роли. Противоречие — оба значения
  названы и разные: уровень, формат работы; оба списка не пусты и не пересекаются: страны и
  города распознанных мест. Роль без компании и роль с пустым названием дублем не бывают. Роли
  одной публикации между собой не сравниваются.
- **П19.** Дубль ищется среди вакансий, публикации которых вышли не дальше 30 дней
  (`DUPLICATE_WINDOW_DAYS`) от публикации роли, в обе стороны по `posted_at`: порядок разбора
  на итог не влияет. Вакансия, выложенная заново позже, — новая. Оригинал — вакансия, записанная
  раньше остальных подходящих.
- **П20.** `saveVacancies` с `skipDuplicates` дубль не пишет: номера `position` получают только
  записанные роли, итог — `SaveSummary` с числом записанных и публикациями-оригиналами дублей.
  Без `skipDuplicates` пишутся все роли: так пишет перенос. Все роли публикации — дубли: её итог
  `duplicate`, `duplicate_of_id` — публикация первой роли-дубля; дублей только часть — итог
  `vacancy`. Итог ставит `mine` через `setOutcome`.

**Технические случаи**

- **E6.** Два запуска пишут одну публикацию одновременно. Вставка — `ON CONFLICT (connector,
  external_id) DO UPDATE` только для строки `failed` (П6): если публикация уже записана с другим
  статусом, ничего не меняется и `insertPublication` отвечает `null`. Вызывающий откатывает
  транзакцию публикации, вакансии не задваиваются; цена — лишние вызовы модели.
- **E8.** Два разбора одновременно пишут одну вакансию из разных каналов — вакансия одна: поиск
  дубля идёт после блокировок ключей компании (E1, `packages/db/src/company/README.md`), второй
  разбор ждёт конца первого и видит его вакансию.
