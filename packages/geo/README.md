# @job-market/geo

Гео-справочник: страны, регионы найма и города, их названия на разных языках. По справочнику
текст вроде «Питер», «UK» или «EU» превращается в место с ключом (`city:498817`, `country:GB`,
`region:eu`), а место — в предков и название для показа.

Данные: 250 стран, 31 802 города (от 15 000 жителей или столица), 8 регионов найма и около
64 тыс. названий. Таблицы `geo_*` лежат в `packages/db/src/geo`, данные приходят миграциями
`packages/db/migrations/*_geo_*.sql`.

## API

`@job-market/geo` — без базы, годится и для клиентского кода:

| Что                                                              | Зачем                                                                                                              |
| ---------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------ |
| `placeKey(place)`, `parsePlaceKey(key)`                          | ключ места в данных: `city:2950159`, `country:DE`, `region:eu`, `anywhere`; неверный ключ — `InvalidPlaceKeyError` |
| `ancestors(place)`, `covers(outer, inner)`, `regionsOf(country)` | предки места и покрытие (П5, П13)                                                                                  |
| `formatPlace(place, locale, city?)`                              | название для показа на ru или en (П15)                                                                             |
| `isAnywhere(text)`                                               | текст означает «откуда угодно» (П10)                                                                               |
| `normalizeName(text)`                                            | нормализация названия (П9)                                                                                         |
| `REGIONS`, `COUNTRY_CODES`, `isCountryCode`                      | регионы найма и коды стран справочника                                                                             |

`@job-market/geo/server` — запросы к базе, принимают клиент или транзакцию drizzle:

| Что                                          | Зачем                                                                                             |
| -------------------------------------------- | ------------------------------------------------------------------------------------------------- |
| `resolvePlaces(db, inputs)`                  | разбор пачки мест одним запросом: `resolved`, `partial` или `unresolved` на каждый вход (П10–П12) |
| `searchPlaces(db, query, { locale, limit })` | автодополнение по началу названия (П14)                                                           |

Сбой базы обе функции возвращают значением `GeoQueryError`, ненайденное место ошибкой не
считается.

## Команды

| Команда                                                                                | Что делает                                                                                                                                                                                                 |
| -------------------------------------------------------------------------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `pnpm geo:build geonames [--refresh]`                                                  | качает дампы GeoNames в `packages/geo/node_modules/.cache/geonames` (`--refresh` — заново), отбирает страны, города и названия (П1–П3), пишет миграцию `…_geo_geonames.sql` и `src/generated/countries.ts` |
| `pnpm geo:build manual`                                                                | из `src/regions.ts` и `src/manual-aliases.ts` пишет миграцию `…_geo_manual.sql`; данные GeoNames не трогает                                                                                                |
| `pnpm --filter @job-market/geo lookup resolve city:Питер "city:Alexandria country:US"` | разбор мест на локальной базе: место, предки, название                                                                                                                                                     |
| `pnpm --filter @job-market/geo lookup search бер [--en]`                               | автодополнение на локальной базе                                                                                                                                                                           |
| `pnpm --filter @job-market/geo test`                                                   | unit- и db-тесты; db-тесты читают справочник в тестовой базе после `pnpm db:migrate:test`                                                                                                                  |

## Как обновить справочник

Справочник меняется только новой миграцией (П6): применённую миграцию не правят.

1. **Регионы или ручные названия.** Поправь `src/regions.ts` или `src/manual-aliases.ts`,
   запусти `pnpm geo:build manual`. Опечатка в коде страны остановит сборку с `ManualDataError`,
   файлы не запишутся.
2. **Данные GeoNames.** `pnpm geo:build geonames --refresh`. Миграция — полный снимок, около
   7 МБ, поэтому обновлять стоит не чаще раза в полгода. Если страна пропала из GeoNames, сборка
   остановится с `CountryRemovedError`: такую выгрузку разбирает человек.
3. `pnpm db:migrate && pnpm db:migrate:test && pnpm test`, затем коммит миграции вместе с
   `src/generated/countries.ts` (П8).

Миграции применяются везде сами: локально — `pnpm dev`, в CI — `pnpm db:migrate:test`, на проде —
сборка Vercel в production (`apps/web/vercel.json`), все новые миграции одной транзакцией. Если
миграция на проде упала, прод остаётся на прошлом деплое. После выкладки нового снимка проверь в
логе сборки время шага `db:migrate`, а на Neon — `count(*)` по `geo_countries`, `geo_cities`,
`geo_aliases` и `pg_database_size`. Если применение на Neon дольше нескольких минут — применяй
миграцию вручную до merge: `NODE_ENV=production pnpm db:migrate`.

## Правила

На номера правил ссылаются комментарии в коде.

**Состав справочника**

- **П1.** Страна — строка `countryInfo` GeoNames, кроме кодов, выведенных из ISO 3166-1: CS
  (Сербия и Черногория) и AN (Нидерландские Антильские острова). XK (Косово) остаётся: его ведут
  GeoNames и CLDR. Названия `name_ru` и `name_en` — из `Intl.DisplayNames`.
- **П2.** Город — строка `cities15000` (от 15 000 жителей или столица), кроме частей города и
  исторических мест: feature code PPLX, PPLH, PPLQ, PPLW, PPLCH.
- **П3.** Названия места из GeoNames: `name` и `asciiname`, для страны — коды alpha-2 и alpha-3, и
  альтернативные названия на ru, en, abbr и первом языке страны из `countryInfo`, кроме
  исторических (`isHistoric`). Повторы после нормализации убираются. `name_ru` и `name_en` города —
  название с `isPreferredName`, иначе первое обычное, иначе первое короткое (`isShortName`);
  разговорные (`isColloquial`) для показа не берутся. `name_en`, совпадающее с `name`, — NULL.
- **П4.** Регионы и их состав задаёт только `src/regions.ts`, ручные названия — только
  `src/manual-aliases.ts`. Код страны, которого нет в `src/generated/countries.ts`, повтор кода
  региона или регион без стран — `ManualDataError`; файлы не пишутся.
- **П5.** Регион A покрывает регион B, если все страны B входят в A: europe покрывает eu и dach,
  а eu не покрывает dach — CH не в ЕС.

**Обновление**

- **П6.** Справочник меняется только новой миграцией от `geo:build`. Применённую миграцию не
  правят: drizzle помнит её хэш и заново не применит. Часть geonames — снимок стран, городов и их
  названий целиком; часть manual — регионы, их состав и ручные названия.
- **П7.** Город и регион не удаляются: пропавшие из источника получают `archived_at`, вернувшиеся —
  снова NULL. Страна не удаляется: если кода из `src/generated/countries.ts` нет в новом
  `countryInfo` — `CountryRemovedError`, файлы не пишутся. Названия заменяются целиком, но только
  своего источника: geonames-миграция не трогает ручные названия, manual — названия GeoNames.
- **П8.** Миграция geonames и `src/generated/countries.ts` пишутся одной командой и коммитятся
  вместе: коды в `geo_countries` и `COUNTRY_CODES` совпадают.

**Разбор и поиск**

- **П9.** Нормализация названия: NFKD, без диакритических знаков, нижний регистр, ё → е, ß → ss,
  всё, кроме букв и цифр, — пробел, пробелы схлопываются, по краям убираются. Одна функция для
  генератора и для запроса, поэтому «Буэнос-Айрес» и «Буэнос Аирес» совпадают: NFKD снимает и
  краткую у «й».
- **П10.** Поле ищется только среди мест своего вида: city — среди городов, country — среди стран,
  region — среди регионов. Архивные города и регионы не участвуют. «worldwide», «anywhere», «весь
  мир», «откуда угодно» в любом поле — место anywhere.
- **П11.** Город выбирается так: если страна в том же входе распознана — только среди её городов.
  Берётся самый населённый кандидат, если он больше следующего хотя бы в 5 раз, иначе —
  неоднозначно. Более точное поле не распознано, а менее точное распознано — `partial`: место — по
  менее точному полю, текст нераспознанного возвращается. Не распознано ничего — `unresolved` с
  причиной `not_found` или `ambiguous`.
- **П12.** Ненайденное место — не ошибка: `resolvePlaces` отвечает на каждый вход в том же
  порядке. Ошибкой значением (`GeoQueryError`) возвращается только сбой базы.
- **П13.** Предки места: город → его страна → регионы этой страны → anywhere; страна → её регионы
  → anywhere; регион → регионы, которые его покрывают (П5) → anywhere. Регионы — от узких к
  широким: по числу стран, при равенстве — по коду. `covers(a, b)` — a есть среди предков b или
  a = b.
- **П14.** Автодополнение: совпадает начало нормализованного названия. Сначала регионы и страны,
  затем города по убыванию населения; каждое место — один раз; не больше `limit`. Запрос короче
  двух символов после нормализации — пустой ответ без запроса в базу.
- **П15.** Показ места: город — «название, страна», где название — `name_ru`, а если его нет —
  `name`; страна и регион — `name_ru`; anywhere — «Откуда угодно». Для en — `name_en` и
  «Anywhere».

**Лицензия**

- **П16.** Данные GeoNames — CC BY 4.0: ссылка на GeoNames и лицензию — в этом README и на каждой
  странице, где показываются гео-данные, с первым таким показом.

## Лицензия данных

Страны, города и их названия — из [GeoNames](https://www.geonames.org/), лицензия
[CC BY 4.0](https://creativecommons.org/licenses/by/4.0/). Мы отбираем строки дампов и
нормализуем названия; регионы найма и ручные названия — наши. Названия стран — из
`Intl.DisplayNames` (данные CLDR).
