# @job-market/classifier

Классификатор публикаций: решает, вакансия ли публикация. Не вакансия — с причиной: `empty`,
если в тексте нет ни одной буквы, и `trash` с пояснением модели во всех остальных случаях.
Модель получает публикацию в общем для моделей виде из `@job-market/publication-text`
(`formatPublication`). Модель — `anthropic/claude-haiku-5.5` через Vercel AI Gateway, без
рассуждений, ключ — `AI_GATEWAY_API_KEY`.

## Ответственность

Пакет отвечает на один вопрос: вакансия ли эта публикация, а если нет — пустая она или мусор.
Он отсекает то, что вакансией явно не является: качество вакансий важнее их числа, поэтому
граница строгая (П1).

| Отвечает                                                | Не отвечает                                                                       |
| ------------------------------------------------------- | --------------------------------------------------------------------------------- |
| что считать вакансией и инструкция модели (`prompt.ts`) | чтение и запись публикаций: статус и причину в базу пишет `connectors`            |
| что считать пустой публикацией (П2)                     | очереди и повторы: перезапускать ли разбор, решает `engine`                       |
| схема ответа модели (`classification.ts`)               | разбор вакансии на роли и поля — это `@job-market/extractor`                      |
| выбор модели и предел вызова                            | раскрытие ссылок — это `@job-market/enricher`, классификатор видит готовый текст  |
| сведение сбоев модели к `ClassificationError`           | вид публикации для модели — `formatPublication` из `@job-market/publication-text` |
| набор проверки `eval/` — качество вердиктов на разметке |                                                                                   |

Зовёт классификатор только `mine` коннекторов (`classifyAndExtract` в `@job-market/connectors`).
Пустоту больше никто не проверяет: `drain` пишет каждую публикацию как `pending`, и до
классификатора доходят все.

## Границы пакета

- **Г1.** Пакет не ходит в базу и не знает об очередях. Всё, что нужно для вердикта, приходит
  аргументом `classify`; результат и ошибка возвращаются значением. Соединение, транзакции,
  id публикации и номер попытки сюда не передаются.
- **Г2.** Из `@job-market/db` — только типы (`import type`), и только через
  `PublicationForModel`. Значения и функции из базы код `src` не импортирует, даже из лёгкого
  входа `@job-market/db/values`. Причины `empty` и `trash` записаны в типе `Classification`;
  с `NOT_VACANCY_REASONS` базы их сверяет компилятор в `@job-market/connectors`, где итог
  пишется. Набор проверки `eval/` — не код пакета: он берёт `CONNECTORS`, чтобы проверить
  разметку случаев.
- **Г3.** Логгер пакет не зовёт. Ошибку `classify` возвращает значением, а в лог её пишет тот,
  кто решает, что с ней делать (правило из `AGENTS.md`).
- **Г4.** Вердикт по умолчанию не подставляется и вызов внутри пакета не повторяется сверх
  повторов AI SDK (П3).
- **Г5.** Правка инструкции, схемы ответа или модели меняет вердикты. После неё — прогон
  `eval` и новый отчёт в `eval/reports/` в том же коммите. Новый вид ошибок модели — сначала
  случай в `eval/cases`, потом правка инструкции.
- **Г6.** `classify` возвращает либо итог, либо `ClassificationError` — третьего вида ответа
  нет. Ошибка — только неполадка: сеть, провайдер, таймаут, ответ не по схеме. Пустая
  публикация и «не вакансия» — итог, а не ошибка.
- **Г7.** Новая причина «не вакансия» нужна, только если по ней будут считать или решать.
  Тогда — значение в `NOT_VACANCY_REASONS` базы с миграцией, вариант в `Classification` и
  случаи в `eval/cases`. Подробности о том, что за пост, идут в `note`, а не в новую причину.

## API

| Что                                             | Зачем                                                                                                    |
| ----------------------------------------------- | -------------------------------------------------------------------------------------------------------- |
| `classify(publication, options?)`               | итог или `ClassificationError` (П1–П3); `options` — модель (`model`) и предел вызова (`timeoutMs`, 60 с) |
| `Classification`                                | итог: `vacancy`, либо `not_vacancy` с причиной `empty`, либо `not_vacancy` с причиной `trash` и `note`   |
| `CLASSIFIER_MODEL_ID`, `defaultClassifierModel` | id модели в AI Gateway и модель по умолчанию                                                             |
| `ClassifyOptions`                               | тип второго аргумента `classify`                                                                         |
| `ClassificationError`                           | модель не дала вердикт: сбой провайдера, таймаут или ответ не по схеме (П3)                              |

```ts
function classify(
  publication: PublicationForModel,
  options?: ClassifyOptions,
): Promise<Classification | ClassificationError>;

type Classification =
  | { kind: 'vacancy' }
  | { kind: 'not_vacancy'; reason: 'empty' }
  | { kind: 'not_vacancy'; reason: 'trash'; note: string };
```

`ClassificationError` возвращается значением, наследник `AppError`.

## Команды

| Команда                                     | Что делает                                                                                                         |
| ------------------------------------------- | ------------------------------------------------------------------------------------------------------------------ |
| `pnpm --filter @job-market/classifier test` | unit-тесты `classify` с моком модели и тесты разметки и подсчёта набора проверки                                   |
| `pnpm --filter @job-market/classifier eval` | прогон набора проверки настоящей моделью; ключ — из окружения или `apps/web/.env.local`, отчёт — в `eval/reports/` |

Набор проверки — 20 размеченных публикаций в `eval/cases`: 7 вакансий и не меньше 4 на каждый
вид «не вакансии» из инструкции. Вид записан в поле `group` случая (`vacancy`, `job_seeker`,
`no_specific_role`, `not_hiring`): в ответ модели он не входит, по нему отчёт показывает, на
каких постах классификатор ошибается. Прогон делает 20 вызовов модели, поэтому в `pnpm test` не
входит. Он печатает долю совпавших вердиктов, совпадения по каждому виду и несовпадения «вид →
что ответили» с id случаев. Вердикт выбирает модель, поэтому П1 проверяет только этот набор, а
не автотест: тест с моком возвращает тот вердикт, который задал сам.

## Правила

На номера правил ссылаются комментарии в коде.

- **П1.** Вакансия — публикация, которая нанимает хотя бы на одну конкретную роль: названа
  должность или понятно, кого ищут; пост канала-агрегатора о чужой вакансии — тоже вакансия.
  Всё остальное с текстом — `not_vacancy` с причиной `trash`: автор сам ищет работу, пост про
  найм без конкретной роли («мы растём», «присылайте резюме»), пост не про найм. Граница
  строгая: сомнительный пост без конкретной роли — `trash`. «Ищем разработчика в команду,
  пишите в личку» — тоже `trash`: нет ни должности, ни уровня, ни стека. К `trash` — пояснение модели в
  `note`: одно-два предложения на русском, что это за пост и почему он не вакансия. У вакансии
  пояснения нет. Определения — в инструкции `src/prompt.ts`, схема ответа модели и тип итога —
  в `src/classification.ts`.
- **П2.** Публикация пустая, если в тексте нет ни одной буквы: пустой текст, одни пробелы,
  только эмодзи, цифры и знаки (`skipReason` из `@job-market/publication-text`). Ссылка состоит
  из букв, поэтому публикация из одной ссылки не пустая: за ссылкой может быть вакансия. На
  пустой публикации `classify` сразу возвращает `not_vacancy` с причиной `empty` и модель не
  зовёт. Причины `empty` и `trash` разделены, чтобы по источникам было видно, кто приносит
  пустые посты, а кто — мусор.
- **П3.** Сбой провайдера, таймаут или ответ не по схеме — `ClassificationError` с исходной
  ошибкой в `cause`. Вердикт по умолчанию не подставляется. Таймаут обрывает вызов вместе с
  повторами AI SDK. Повторять ли вызов и что записать, решает вызывающий; id публикации к ошибке
  добавляет он же: `classify` его не знает.
