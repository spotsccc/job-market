# @job-market/classifier

Классификатор публикаций: решает, вакансия ли публикация, и если нет — почему. Модель получает
публикацию в общем для моделей виде из `@job-market/publication-text` (`formatPublication`) и
отвечает вердиктом с пояснением по схеме. Модель — `anthropic/claude-haiku-5.5` через Vercel AI
Gateway, без рассуждений, ключ — `AI_GATEWAY_API_KEY`.

## API

| Что                                             | Зачем                                                                                                        |
| ----------------------------------------------- | ------------------------------------------------------------------------------------------------------------ |
| `classify(publication, options?)`               | вердикт и пояснение (П1); `options` — своя модель (`model`) и предел вызова (`timeoutMs`, по умолчанию 60 с) |
| `Classification`, `Verdict`, `VERDICTS`         | ответ классификатора и значения вердикта: `vacancy` и причины из `NOT_VACANCY_REASONS` (П1)                  |
| `CLASSIFIER_MODEL_ID`, `defaultClassifierModel` | id модели в AI Gateway и модель по умолчанию                                                                 |
| `ClassifyOptions`                               | тип второго аргумента `classify`                                                                             |
| `NothingToClassifyError`                        | в тексте нет ни одной буквы, модель не звалась (П2)                                                          |
| `ClassificationError`                           | модель не дала вердикт: сбой провайдера, таймаут или ответ не по схеме (П3)                                  |

Обе ошибки `classify` возвращает значением, наследники `AppError`.

## Команды

| Команда                                     | Что делает                                                                                                         |
| ------------------------------------------- | ------------------------------------------------------------------------------------------------------------------ |
| `pnpm --filter @job-market/classifier test` | unit-тесты `classify` с моком модели и тесты разметки и подсчёта набора проверки                                   |
| `pnpm --filter @job-market/classifier eval` | прогон набора проверки настоящей моделью; ключ — из окружения или `apps/web/.env.local`, отчёт — в `eval/reports/` |

Набор проверки — 20 размеченных публикаций в `eval/cases`: 8 вакансий и по 4 на каждую причину
«не вакансия». Прогон делает 20 вызовов модели, поэтому в `pnpm test` не входит. Он печатает долю
совпавших вердиктов, совпадения по каждому вердикту и несовпадения «ждали → получили» с id
случаев. Вердикт выбирает модель, поэтому П1 проверяет только этот набор, а не автотест: тест с
моком возвращает тот вердикт, который задал сам.

## Правила

На номера правил ссылаются комментарии в коде.

- **П1.** Вердикт — одно из четырёх. `vacancy` — публикация нанимает хотя бы на одну конкретную
  роль: названа должность или понятно, кого ищут; пост канала-агрегатора о чужой вакансии — тоже
  вакансия. `job_seeker` — автор сам ищет работу. `no_specific_role` — про найм, но без
  конкретной роли. `not_hiring` — не про найм. К вердикту — пояснение одним предложением на
  русском. Определения — в инструкции `src/prompt.ts`, значения — в схеме `src/classification.ts`.
- **П2.** Разбирать нечего, если в тексте нет ни одной буквы: пустой текст или одни пробелы —
  `empty`, только эмодзи, цифры и знаки — `no_words` (`skipReason` из
  `@job-market/publication-text`). Ссылка состоит из букв, поэтому публикация из одной ссылки
  разбирается: за ссылкой может быть вакансия. `classify` на таком тексте возвращает
  `NothingToClassifyError` с причиной и модель не зовёт. Код разбора отсекает такие публикации
  раньше, так что эта ошибка значит, что вызывающий пропустил проверку.
- **П3.** Сбой провайдера, таймаут или ответ не по схеме — `ClassificationError` с исходной
  ошибкой в `cause`. Вердикт по умолчанию не подставляется. Таймаут обрывает вызов вместе с
  повторами AI SDK. Повторять ли вызов и что записать, решает вызывающий; id публикации к ошибке
  добавляет он же: `classify` его не знает.
