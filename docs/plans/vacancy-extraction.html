Новый экстрактор и перенос постов в новую модель

Статус: требует ревью
Как владелец, я хочу, чтобы посты, которые уже есть в базе, прошли через новый экстрактор и заполнили новую таблицу вакансий профессией из дерева профессий, местами из гео-справочника, опытом, языками, навыками двумя списками и разделами описания, чтобы новая модель сразу была заполнена подробными вакансиями, а качество разбора было видно цифрами.

1Задача

Новая модель данных и гео-справочник уже в коде. Старые таблицы называются legacy_posts и legacy_vacancies, новые таблицы созданы пустыми, а @job-market/geo сводит места к справочнику функцией resolvePlaces. Этот план даёт экстрактор, который пишет вакансию по новой модели, и скрипт, который прогоняет через него посты из legacy_posts.

Экстрактор становится пакетом над текстом. Он возвращает роли публикации: прежние поля, профессию — узел дерева occupations, места словами текста, опыт в годах, языки с уровнем, навыки «обязательно» и «будет плюсом», разделы описания списками. Места сводятся к гео-справочнику после экстрактора. Качество меряет набор из 29 размеченных текстов: без него правку промпта не с чем сравнить.

Перенос — скрипт, который владелец запускает со своей машины против продовой базы. Он берёт посты пачками и пишет по каждому публикацию, автора, вакансии и их места одной транзакцией. Посты со ссылками на вакансии и посты LinkedIn перенос сначала дополняет прочитанным по ссылкам: это делает енричер — пакет @job-market/enricher. Повторный запуск продолжает с того места, где остановился прошлый. Переключение /vacancies на новые таблицы и удаление legacy-таблиц — следующий шаг после сверки S6.

Путь сценария шаг за шагом

Схема последовательности по UML: участники сверху, время идёт вниз. Сообщение идёт только от вызывающего к вызываемому, ответ возвращается тем же путём. Рамки — фрагменты: в alt выполняется одна ветка, loop повторяется. Кнопка «Шаг ▶» проходит схему по одному сообщению и объясняет его.

4Модель данных

Таблицы

Не применимо: таблиц не добавляется и не меняется. Все таблицы, в которые пишет перенос, создала миграция 0008_data_model; описание столбцов — в packages/db/src/publication, occupation и vacancy. Этот план только наполняет их строками.

Столбцы, которые заполняет перенос. Остальные получают DEFAULT из схемы или остаются NULL.
