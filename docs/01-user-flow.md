# Пользовательский флоу (v1, один пользователь)

Задача v1: раз в день получать короткий список новых вакансий с LinkedIn, которые подходят под мой опыт — включая смежные роли, которые я сам не стал бы искать по названию, — и быстро их разбирать.

Главная идея: пользователь не пишет поисковые запросы. Он описывает себя, система сама строит план поиска (роли + запросы), показывает его на ревью, а дальше каждая найденная вакансия получает оценку соответствия с объяснением.

## 1. Онбординг (один раз, ~10 минут)

### Шаг 1. Рассказать о себе

| Что | Формат | Обязательно |
|---|---|---|
| Резюме | PDF или текст (подойдёт экспорт профиля LinkedIn в PDF) | да |
| «Что я ищу» | свободный текст, 3–10 предложений: что нравится делать, куда хочется расти, чего не хочется | да |
| Ссылки (GitHub, портфолио) | текст | нет |

Свободный текст важнее, чем кажется: именно из него система понимает, что «frontend + AI‑пайплайны + агенты» — это не только Frontend Engineer.

### Шаг 2. Жёсткие ограничения

Короткая форма. Всё, что здесь указано, работает как фильтр, а не как пожелание:

- **Локации и формат**: список регионов/стран + remote / hybrid / onsite. Каждая локация умножает число запросов к LinkedIn, поэтому 1–3 на старте.
- **Право на работу / часовые пояса**: где могу работать без визы, приемлемый сдвиг по времени.
- **Уровень**: например senior / staff / lead.
- **Тип занятости**: full‑time, contract.
- **Минимальная компенсация** (необязательно; на LinkedIn зарплата указана редко, поэтому вакансии без зарплаты не отсекаются).
- **Языки** описания вакансии и работы.
- **Исключения**: компании, слова в названии («Angular», «intern», «PHP»), отрасли (gambling и т.п.), агентства/аутстафф.

### Шаг 3. Ревью плана поиска

Система (LLM) превращает шаги 1–2 в структурированный профиль и план поиска и показывает их на одном экране:

- **Навыки** — чипы с уровнем (core / уверенно / знаком). Можно удалить, добавить, поменять уровень.
- **Целевые роли в трёх группах**, у каждой чекбокс и раскрывающийся список запросов:

| Группа | Смысл | Пример для frontend + AI‑профиля |
|---|---|---|
| Core | то, чем я занимаюсь сейчас | Senior Frontend Engineer, React / Next.js Engineer, UI Engineer |
| Adjacent | тот же стек, другой акцент | Full‑stack (TypeScript) Engineer, Product Engineer, AI Engineer (TypeScript), Design Engineer, Founding Engineer |
| Stretch | переход, под который есть опыт | Applied AI / AI Agent Engineer, Forward Deployed Engineer, Solutions Engineer (AI), Developer Experience / DevRel Engineer |

- **Запросы** — что реально уйдёт в поиск LinkedIn, например `"frontend engineer" AND (AI OR LLM OR agents)`, `"product engineer" AND (React OR "Next.js")`, `"AI engineer" AND TypeScript`. Можно отредактировать или добавить свой.

Кнопка **«Запустить первый сбор»**.

### Шаг 4. Первый сбор и калибровка

- Первый сбор идёт в фоне 30–90 минут (глубина — последние 14 дней). На экране прогресс: найдено карточек → прошло отбор по названию → оценено.
- Когда набралось 20 оценённых вакансий, система показывает **калибровочную выборку**: по несколько вакансий с высокой, средней и низкой оценкой. Я отмечаю 👍 / 👎 и, по желанию, причину. Эти отметки становятся примерами в промпте оценки.

Калибровка — самый дешёвый способ поднять качество: после неё оценки заметно ближе к моему вкусу, а не к «среднему senior‑разработчику».

## 2. Ежедневное использование

### 2.1 Дайджест в Telegram

Раз в день (после утреннего сбора) приходит одно сообщение:

```
🆕 7 новых подходящих вакансий (из 143 найденных)

92 · Product Engineer, AI Agents — Acme · Remote EU · 3 ч назад
     React/Next.js + агентные пайплайны, маленькая команда
88 · Senior Frontend Engineer (LLM tooling) — Foo · Berlin, hybrid · вчера
     ...
[Открыть все 7 →]
```

Порог (по умолчанию ≥ 75) и время настраиваются. Если подходящих нет — сообщение не приходит. Сохранённая вакансия закрылась — отдельная строка в дайджесте.

### 2.2 Inbox — основной экран

```
┌──────────────────────────────────────────────────────────────────────────┐
│ Inbox (7 новых)   Сохранённые (12)   Откликнулся (4)   Поиск   Профиль   │
├──────────────────────────────────────────────────────────────────────────┤
│ Группа роли: [Все ▾]  Формат: [Remote ▾]  Оценка: [≥ 60 ▾]  За: [7 дн ▾] │
├───────────────────────────────┬──────────────────────────────────────────┤
│ 92 Product Engineer, AI Agents│ Product Engineer, AI Agents · Acme       │
│    Acme · Remote EU · 3 ч     │ Remote EU · full‑time · 3 ч назад · 41   │
│    adjacent                   │ откликов · $‑‑                           │
│ ───────────────────────────── │                                          │
│ 88 Sr Frontend (LLM tooling)  │ Почему подходит                          │
│    Foo · Berlin hybrid · 1 д  │  • Next.js + React — основной стек       │
│    core                       │  • Строить UI для агентных пайплайнов    │
│ ───────────────────────────── │  • Команда 8 человек, product ownership  │
│ 81 Forward Deployed Engineer  │ Чего не хватает                          │
│    Bar · London · 2 д         │  • Python в проде (у меня — эпизодически)│
│    stretch · ещё 3 локации    │ Красные флаги                            │
│                               │  • нет                                   │
│                               │                                          │
│                               │ [Сохранить s] [Скрыть x] [Откликнулся a] │
│                               │ [Открыть на LinkedIn ↗]                  │
│                               │ ▸ Полное описание                        │
└───────────────────────────────┴──────────────────────────────────────────┘
```

- Слева лента, отсортированная по оценке; справа карточка выбранной вакансии.
- На карточке: оценка 0–100, группа роли, 2–4 пункта «почему подходит», «чего не хватает», красные флаги (только US‑резиденты, on‑site 5 дней, агентство и т.п.), извлечённые поля (стек, уровень, формат, зарплата), число откликов, ссылка на LinkedIn.
- Одинаковая вакансия в нескольких городах или перевыложенная — одна карточка с пометкой «ещё N локаций / перевыложена».
- **Действия**: Сохранить, Скрыть (с причиной одним кликом: не тот стек / не тот уровень / локация / компания / другое), Откликнулся. Причины скрытия копятся и раз в неделю предлагаются как правка профиля («ты 6 раз скрыл вакансии с обязательным Python — добавить в ограничения?»).
- **Клавиатура**: `j/k` — навигация, `s` — сохранить, `x` — скрыть, `a` — откликнулся, `o` — открыть на LinkedIn. Разбор 10 вакансий должен занимать пару минут.

Отклик происходит на LinkedIn/сайте компании; система только хранит статус.

### 2.3 Статусы вакансии для пользователя

`new → seen → saved → applied`, в любой момент `hidden`. Отдельно — состояние самой вакансии: `active / closed / stale` (см. техспеку). Закрытые вакансии уходят из Inbox, но остаются в Сохранённых с пометкой.

## 3. Быстрый поиск по базе

Вкладка «Поиск» — полнотекстовый поиск по всем собранным вакансиям, включая те, что получили низкую оценку или не оценивались вовсе:

- строка запроса (название, компания, текст описания);
- фильтры: формат, локация, дата, группа роли, оценка, статус, компания;
- сортировка по дате или оценке.

Сценарии: «покажи всё с `LangGraph` за месяц», «что сейчас открыто у компании X», «все вакансии Design Engineer независимо от оценки».

## 4. Профиль и план поиска

Вкладка «Профиль»:

- правка навыков, ограничений, текста «что я ищу»;
- план поиска со статистикой по каждому запросу: сколько карточек нашёл, сколько прошло отбор, сколько получило оценку ≥ 75, сколько я сохранил. Запросы, которые дают только шум, видно сразу — их можно выключить;
- кнопка «Предложить новые роли» — LLM смотрит на сохранённые вакансии и предлагает роли/запросы, которых нет в плане;
- после правки профиля — кнопка «Пересчитать оценки за последние 14 дней».

## 5. Аналитика рынка (этап 2)

В v1 интерфейса аналитики нет, но данные для неё копятся с первого дня: из каждой вакансии с загруженным описанием извлекаются стек, уровень, формат, зарплата, тип компании. Позже на этом строятся: частота навыков по ролям, динамика числа вакансий, зарплатные вилки, доля remote, «какие навыки чаще всего стоят рядом с моими».

## 6. Что не входит в v1

- Другие источники (Indeed, X, Threads и т.д.) — интерфейс источника закладывается, реализация только LinkedIn.
- Автоотклик, генерация сопроводительных писем.
- Несколько пользователей, регистрация.
- Дашборды аналитики.
- Мобильное приложение (хватает Telegram‑дайджеста и адаптивной веб‑страницы).
