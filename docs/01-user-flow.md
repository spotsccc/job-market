# Пользовательский флоу (v1, один пользователь)

Задача v1: дважды в день собирать новые вакансии с LinkedIn, которые подходят под мой опыт — включая смежные роли, которые я сам не стал бы искать по названию, — и быстро их просматривать.

Главная идея: пользователь не пишет поисковые запросы. Он описывает себя, система сама строит план поиска (роли + запросы), показывает его перед стартом, а дальше каждая найденная вакансия получает оценку соответствия с объяснением.

Моки всех экранов — в [mockups/](./mockups/README.md).

## 1. Онбординг (один раз, ~10 минут)

Три шага: **О себе → Запросы → Первый сбор**.

### Шаг 1. О себе

| Что | Формат | Обязательно |
|---|---|---|
| Резюме | PDF или текст (подойдёт экспорт профиля LinkedIn в PDF) | да |
| «Что я ищу» | свободный текст, 3–10 предложений: что нравится делать, куда хочется расти, чего не хочется | да |

Свободный текст важнее, чем кажется: именно из него система понимает, что «frontend + AI‑пайплайны + агенты» — это не только Frontend Engineer. Из него же и из резюме LLM извлекает навыки с уровнями, желаемый уровень позиции, тип занятости, минимальную компенсацию и исключения («не хочу: Angular, вёрстку лендингов» → исключения по стеку). Отдельной формы ограничений нет — всё это видно и правится через профиль.

### Шаг 2. Где искать и какие запросы будут выполняться

Один экран, на котором видно ровно то, что уйдёт в поиск LinkedIn.

**Где искать.** Список локаций, у каждой — любой набор форматов Remote / Hybrid / Офис. Пример:

| Локация | Форматы | Что уходит в LinkedIn |
|---|---|---|
| Аргентина | Remote, Hybrid, Офис | `location=Argentina&f_WT=1,2,3` |
| США | Remote | `location=United States&f_WT=2` |
| Европейский союз | Remote | `location=European Union&f_WT=2` |

- Локацию можно ввести (страна, регион, город) или выбрать из частых вариантов; удалить — крестиком.
- Форматы одной локации ищутся одним запросом и не увеличивают число поисков (`f_WT` с несколькими значениями — проверить в спайке M0; если не работает, каждый формат станет отдельным поиском).
- Локация без выбранного формата подсвечивается и не ищется.

Почему локация нужна: мы смотрим только верх выдачи (по дате, до 5 страниц на поиск), и без локации его займут вакансии со всего мира, в основном из США. Remote в LinkedIn — фильтр формата, а не локация: у remote‑вакансии почти всегда есть регион найма («Remote, US only»), поэтому «удалёнка в ЕС» = `location=European Union` + `f_WT=2`. Вакансии, недоступные мне по региону найма, дополнительно ловятся при оценке (красный флаг / не попадают в Inbox).

**Запросы.** Таблица, которую LLM составила по шагу 1:

| Колонка | Смысл |
|---|---|
| Вкл | выключенный запрос не ищется |
| Запрос | точная строка для LinkedIn, например `"product engineer" AND (React OR "Next.js")` |
| Под какую роль | Product Engineer, AI Engineer (TypeScript), Forward Deployed Engineer… |
| Группа | core / adjacent / stretch (ниже) |
| Поисков | × число локаций |
| Показать URL | конкретные ссылки поиска по каждой локации |

| Группа | Смысл | Пример для frontend + AI‑профиля |
|---|---|---|
| Core | то, чем я занимаюсь сейчас | Senior Frontend Engineer, React / Next.js Engineer, UI Engineer |
| Adjacent | тот же стек, другой акцент | Full‑stack (TypeScript) Engineer, Product Engineer, AI Engineer (TypeScript), Design Engineer, Founding Engineer |
| Stretch | переход, под который есть опыт | Applied AI / AI Agent Engineer, Forward Deployed Engineer, Solutions Engineer (AI), Developer Experience / DevRel Engineer |

Под таблицей — поле «Свой запрос», параметры сбора (первый сбор — 14 дней, дальше — с прошлого прогона; сортировка по дате, до 5 страниц) и итог: «13 запросов × 3 локации = 39 поисков за прогон». Кнопка **«Запустить первый сбор»**.

### Шаг 3. Первый сбор

- Идёт в фоне 30–90 минут, глубина — последние 14 дней; вкладку можно закрыть.
- На экране воронка: найдено карточек → прошли исключения → прошли отбор по названию (LLM) → загружено описаний → уникальных после склейки дублей → оценено. Рядом — журнал прогона (в том числе паузы после 429 от LinkedIn) и «лучшие на сейчас».
- Как только появились первые оценки — кнопка **«Открыть Inbox»**; сбор продолжается, новые вакансии появляются там же.
- Дальше сбор идёт сам, в 08:00 и 18:00.

## 2. Inbox — основной экран

Навигация приложения: **Inbox · База · Профиль**.

```
┌──────────────────────────────────────────────────────────────────────────┐
│ job-market   Inbox (6)   База   Профиль        Сбор: 08:12 · след. 18:00 │
├───────────────────────────────┬──────────────────────────────────────────┤
│ 92 Product Engineer, AI Agents│ 92  Product Engineer, AI Agents          │
│  • Lumen Labs · Remote EU · 3ч│     Lumen Labs · Remote, EU              │
│    adjacent                   │     3 ч назад · 41 отклик · Full‑time    │
│ ───────────────────────────── │                                          │
│ 88 Sr Frontend (LLM tooling)  │ Группа · Уровень · Зарплата · Компания   │
│  • Northwind AI · Buenos Aires│ Стек: Next.js React TypeScript Python    │
│    core                       │                                          │
│ ───────────────────────────── │ Почему подходит │ Чего не    │ Красные   │
│ 81 Forward Deployed Engineer  │  • Next.js…     │ хватает    │ флаги     │
│  • Fieldnote · Remote US · 2д │  • UI для агент…│  • Python… │  нет      │
│    stretch · ещё 2 локации    │                                          │
│                               │ ▸ Полное описание                        │
└───────────────────────────────┴──────────────────────────────────────────┘
```

- **Слева** лента, отсортированная по оценке. В строке: оценка, название, компания, локация, давность, группа роли; синяя точка — вакансия ещё не открывалась; пометки «ещё N локаций» / «перевыложена» — одинаковая вакансия в нескольких локациях или перевыложенная показывается одной карточкой.
- **Справа** карточка выбранной вакансии:
  - оценка 0–100, название, компания, локация, давность, число откликов, тип занятости;
  - пометка о дублях, если есть;
  - извлечённые поля: группа роли, уровень, зарплата, тип и размер компании;
  - стек из описания: зелёным — что у меня есть, жёлтым — чего нет;
  - «Почему подходит» (2–4 пункта), «Чего не хватает», «Красные флаги» (только US‑резиденты, офис 5 дней, много командировок и т.п.);
  - полное описание раскрывается по клику.

Статус вакансии для меня — только `новая → просмотрена` (при открытии). Состояние самой вакансии — `активна / закрыта / устарела` (см. техспеку): закрытые и устаревшие уходят из Inbox и остаются в Базе.

## 3. База

Полнотекстовый поиск по всем собранным вакансиям, включая те, что получили низкую оценку или не оценивались вовсе (отсеяны по названию, исключением или правилом «агентство»):

- строка запроса (название, компания, текст описания) и быстрые сценарии: «всё с `LangGraph` за месяц», «что открыто у компании X», «все Design Engineer независимо от оценки»;
- фильтры: формат, локация, дата, группа роли, оценка (включая неоценённые), статус (новые / закрытые / только активные);
- сортировка по дате или по оценке;
- в результатах: дата, оценка или причина, почему вакансия не оценивалась, название и компания с подсвеченным совпадением, локация, группа, статус.

## 4. Профиль

- **Обо мне**: текст «что я ищу», навыки по уровням (core / уверенно / знаком), локации, уровень и занятость, минимум, исключения — всё извлечено из шага 1. «Изменить» ведёт к тексту «что я ищу».
- **Где искать**: тот же блок локаций и форматов, что на шаге 2.
- **План поиска** со статистикой за 14 дней по каждому запросу: сколько карточек нашёл, сколько прошло отбор, сколько получило оценку ≥ 75 и «польза» — доля карточек с оценкой ≥ 75. Запрос, который нашёл больше 100 карточек и ни одной ≥ 75, помечен «шум» — его можно выключить. Внизу итог: включено запросов × локаций = поисков за прогон.

## 5. Что не входит в v1

- Уведомления (в том числе Telegram‑дайджест) — новое смотрим в Inbox.
- Калибровка оценок отметками «подходит / не подходит».
- Действия с вакансией: сохранить, скрыть с причиной, отметить отклик; горячие клавиши, фильтры в Inbox, еженедельные подсказки по правке профиля.
- Отдельный шаг жёстких ограничений, ссылки на GitHub / портфолио.
- «Предложить новые роли» и пересчёт оценок по кнопке.
- Другие источники (Indeed, X, Threads и т.д.) — интерфейс источника закладывается, реализация только LinkedIn.
- Автоотклик, сопроводительные письма, несколько пользователей, аналитика рынка, мобильное приложение (хватает адаптивной веб‑страницы).
