# Перенос постов

Перенос постов `legacy_posts` в новую модель: публикации, авторы, ссылки, вакансии и их места.
Пост проходит енричер, экстрактор и гео-справочник, без классификатора (П5), и пишется одной
транзакцией. Это единственный код, который читает старую модель и пишет новую; его удалят вместе
с `legacy_posts` после сверки.

Как запустить и что значит итог — в разделе
[«Перенос постов в новую модель»](../../../../README.md#перенос-постов-в-новую-модель) корневого
README. Правила записи публикаций, авторов и вакансий — в `packages/db/src/publication/README.md`,
разбора ролей — в `packages/extractor/README.md`.

## API

| Что                                                                        | Зачем                                                                                                                                  |
| -------------------------------------------------------------------------- | -------------------------------------------------------------------------------------------------------------------------------------- |
| `transferPosts({ db, readers, limit?, dryRun?, model? })` из `transfer.ts` | перенос пачками по 20 (П1–П8), ответ — итог `TransferSummary`; останавливается после пачки, где упали все вызовы модели (E8)           |
| `apps/web/scripts/transfer-posts.ts`                                       | скрипт `vacancies:transfer`: база по `NODE_ENV`, читатели ссылок через `createReaders`, печать итога и сверка после настоящего запуска |
| `mapPost(post)` из `map-post.ts`                                           | источник, автор и поля публикации поста (П2, П3)                                                                                       |
| `prepareBatch` из `prepare.ts`                                             | итог каждого поста пачки до записи: енричер, пустые и копии, экстрактор, справочник (П4–П6, П8); в базу не пишет                       |
| `writeBatch` из `write.ts`                                                 | запись пачки по порядку, пост — своя транзакция (П1, E5)                                                                               |

## Правила

На номера правил ссылаются комментарии в коде. Номера — из плана переноса, поэтому с пропусками.
Части П3, П4 и П6 о записи в базу — в `packages/db/src/publication/README.md` под теми же
номерами, часть П5 об ответе без ролей — в `packages/extractor/README.md`.

**Порядок и попытки**

- **П1.** Запуск берёт посты, у которых нет публикации с тем же id или есть публикация `failed`
  с `attempts` меньше 3, по `(posted_at, id)` от старых к новым, не больше `--limit`. Пачки идут
  курсором по `(posted_at, id)`: каждый пост пробуется один раз за запуск, в том числе при
  `--dry-run`. Пост пишется целиком или никак: автор, публикация, её ссылки, вакансии и места —
  одной транзакцией. Почему от старых к новым: из двух копий одного текста оригиналом становится
  та, что опубликована раньше (П4).

**Пост в новой модели**

- **П2.** Публикация поста: id — id поста; `connector` по `source`: telegram → open-telegram,
  linkedin → linkedin; `external_id`, `url` и `posted_at` — без изменений, `content` — текст с
  разделами енричера (П8). Почему тот же id: «перенесён ли пост» проверяется без таблицы
  соответствий.
- **П3.** Источник: telegram — open-telegram с ключом-каналом из `external_id` до «/»; linkedin —
  linkedin с ключом `manual`. Источники заводит миграция `0010_occupations_sources`; источника нет
  в базе — пост становится ошибкой запуска, публикация не пишется. Автор: telegram — канал,
  linkedin — путь профиля из `author_url` (`in/jane-doe`, `company/acme`); ни `in/`, ни
  `company/` в пути — публикация пишется без автора с предупреждением в логе. `name`, `url` и
  `headline` автора — из `author_name`, `author_url`, `author_headline`; как они перезаписываются
  — П3 в `packages/db/src/publication/README.md`.

**Итог поста**

- **П4.** Копии. Пост, у хэша которого есть оригинал в базе или записанный раньше в этом
  запуске, пишется `duplicate` с `duplicate_of_id` оригинала, без экстрактора и вакансий. Копии
  в одной пачке ждут свой оригинал: экстрактор зовётся для первой по порядку П1, остальные
  пишутся `duplicate` после неё, если она записана `vacancy` или `not_vacancy`; иначе они не
  пишутся и ждут следующего запуска. Оригинал, который упал в прошлых запусках, не мешает: его
  копия сама становится оригиналом. Хэш и что такое оригинал — П4 в
  `packages/db/src/publication/README.md`. Почему: одну вакансию публикуют в нескольких
  каналах, разбирать её дважды — платить дважды.
- **П5.** Экстрактор нашёл роли — `vacancy`. Ролей нет — `extract` возвращает `Error`, пост —
  ошибка по П6. Пустой текст (одни пробелы) — `not_vacancy` с причиной `empty`, без пояснения
  и без вызова модели. Классификатор не вызывается. `attempts` растёт на 1 при каждой
  попытке, `processed_at` — время переноса.
- **П6.** Ошибка экстрактора или справочника (`GeoQueryError`) на посте: вакансии не пишутся,
  публикация пишется `failed` с причиной в `last_error`, запуск идёт дальше, пост попадает в
  ошибки итога. Следующий запуск пробует его снова, пока `attempts` меньше 3 (П1); после третьей
  ошибки он остаётся `failed` и виден в сверке. Ошибка записи в базу откатывает транзакцию
  поста: публикации нет, следующий запуск берёт пост снова. Места всех ролей пачки сводятся
  одним вызовом, поэтому сбой справочника — ошибка всех постов пачки, у которых экстрактор нашёл
  роли. Почему `failed` пишется: иначе пост, на котором модель падает всегда, не даёт закончить
  перенос.
- **П7.** `--dry-run` делает всё, что перенос, включая вызовы модели и енричера, но каждая
  транзакция откатывается; итог печатается тот же, «осталось» не меняется. Копия оригинала из
  этого же пробного запуска только считается: оригинала в базе нет.

**Ссылки**

- **П8.** Перед экстрактором тексты пачки идут в `enrich` пакета `@job-market/enricher`, дальше
  перенос работает с текстом с разделами: его получает экстрактор и он пишется в
  `publications.content`; хэш считается по тексту поста без разделов. Ссылка, которая не
  прочиталась, пост не останавливает: он идёт в экстрактор без её раздела, повтора нет. Что
  енричер сделал с каждой ссылкой текста, пишется в `publication_links` той же транзакцией, что
  публикация: `read`, `no_data`, `failed` с ошибкой одной строкой, `unsupported`, `over_limit`.
  Итог запуска считает ссылки по статусам. Почему не ошибка поста: из-за посторонней ссылки пост
  не должен падать, а по `publication_links` видно, какие читатели добавить.

**Технические случаи**

- **E5.** Запуск оборвался посередине (Ctrl+C, сон ноутбука, разрыв соединения): каждый пост —
  своя транзакция, записанные остаются целиком, незаписанный откатывается. Следующий запуск
  берёт посты без публикации и `failed` (П1).
- **E7.** Две копии одного текста в одной пачке, хэша ни одной ещё нет в базе: копии ищутся и в
  базе, и внутри пачки до вызова модели, модель зовётся только для первой (П4).
- **E8.** AI Gateway отвечает 429 или кончились кредиты: каждый пост пачки — ошибка (П6). Если в
  пачке не записан ни один пост и все ошибки — сбой самого вызова модели, запуск
  останавливается после неё с «все вызовы модели упали: <первая ошибка>» и кодом выхода 1. Ответ
  не по схеме, в том числе без ролей, и сбой справочника таким сбоем не считаются.
